# PKAF v0.1.1 Release Manifest

**Release name:** PKAF v0.1.1 — Structural validation fix and consumer-justification shapes
**Release date:** 2026-05-12
**Bridge contract:** `pkaf-bridge/1.0`
**Profile:** PKAF-SHACL-AF

## Release note

v0.1.1 preserves PKAF v0.1 semantics but rewrites conditional SHACL constraints into pySHACL-evaluated Pattern C form, patches six fixture defects exposed by the corrected constraints, and adds generated-artifact / consumer-justification overlay shapes. The combined package validates cleanly across **1,206 triples with 0 violations**.

This release also generalizes the public framing of PKAF. Earlier drafts positioned PKAF as feeding "WOS and Formspec." v0.1.1 corrects that: PKAF is a universal evidence-backed assertion, authority, concept, lifecycle, and consumer-justification data ontology. Consumer systems may include search engines, wikis, form builders, workflow engines, case systems, content management systems, AI assistants, publication systems, auditing tools, or knowledge graphs. The fixtures use form-like and workflow-like artifacts as stress tests for the consumer overlay pattern; they are examples, not dependencies.

## What changed from v0.1-rc1

| Category | Change |
|---|---|
| **Spec semantics** | No change. PKAF Core §1-§7 and ConceptRegistry §1-§10 are textually identical to v0.1-rc1. |
| **JSON-LD context** | Additive only. `pkaf:definedInScope` typing added as @id (was missing in v0.1). Documented in `_meta` block. |
| **Shape files** | Pattern C rewrite for 8 conditional shapes (3 Core, 3 ConceptRegistry, 1 Lifecycle, 1 Justification). Three new generic consumer-overlay shapes added (`ConsumerArtifactJustificationShape`, `DataCollectionArtifactJustificationShape`, `ProcessArtifactJustificationShape`). `FormspecFieldJustificationShape` and `WOSStepJustificationShape` retained as documented example specializations. |
| **Fixtures** | Six latent defect patches: 4 A3 assertions missing authorityKind/applicability, 1 acceptedWithWarnings result missing structured warnings, 1 rejected result missing remediation. +20 triples (1,186 → 1,206). |
| **CI gate** | Multi-mode (`--mode core / batch2 / batch3 / batch4`). Default mode `batch4`. |
| **Public framing** | README rewritten. PKAF positioned as universal ontology; consumer systems are examples, not anchors. |

## What v0.1.1 does NOT do

Per the explicit boundaries maintained across all four batches:

- Does not validate consumer-system internals (Formspec schema, WOS workflow runtime, search ranking, CMS storage, etc.)
- Does not validate cascade closure correctness (runtime test, not structural shape)
- Does not validate reducer output correctness (runtime test)
- Does not validate concept cache TTL or registry liveness (runtime test)
- Does not include a SHACL-Core-only compatibility profile (one `qualifiedValueShape` use in AuthorityAssertionShape requires SHACL-AF)

## Next layer: runtime conformance tests

With v0.1.1 the structural validation surface is functionally complete for v0.1.x. The next layer of work is runtime conformance tests — fixture-specific expected-output JSON files that consumer implementations diff against their actual output.

### Format

```yaml
input:
  fixture: <fixture-id>
  trigger: <packet-id-or-event-id>
expected:
  affectedAssertions: [...]
  affectedAdoptions: [...]
  affectedWorkProducts: [...]
  authorityChainStatus: <enum>
  pointInTimeExceptionAccepted: <boolean>
  ...
```

### Initial test suite

| # | Input | Tests |
|---|---|---|
| 1 | statutory-authority + rescission-001 | CascadeClosureV1 affected set, authority chain status, PIT exception acceptance |
| 2 | local-operational + amend-001 | CascadeClosureV1 affected set on local amendment, work-product cascade |
| 3 | mapping + lifecycle-001 (split) | ConceptLifecyclePacket cascade, successor handling |
| 4 | registry-failure-conflict (case-1 through case-9) | Registry-unavailable behavior, cache-staleness behavior, conflict resolution |
| 5 | statutory-authority RevalidationEvent | Reducer output for staleForCurrentUse transition, PIT exception preservation |
| 6 | mapping caa-77 (proposed adoption) | usageEligibility reducer ceiling behavior |
| 7 | registry-failure-conflict case-9 | safeAutomaticMigration replaceInPlace semantics |
| 8 | local-operational + req-002 amend cascade | LocalAdoption orphaning and re-adoption flow |

These tests are imported by consumer implementations (search engines, wikis, form builders, workflow engines, etc.) which run their own cascade/reducer/traversal logic and diff against the expected output. Differences are conformance failures.

This work begins in the next iteration cycle, after external review of v0.1.1.

## Sign-off

v0.1.1 is the first PKAF release whose structural validation gate is fully honest about what it enforces. The Pattern C rewrite means every conditional constraint declared in the shape files actually evaluates against fixture data. The six latent fixture defects have been patched. The consumer-overlay shape vocabulary is now generic at its conceptual center, with consumer-specific shapes (Formspec, WOS) retained as documented example specializations.

Four batches. Four iteration arcs. Zero spec drift. Zero new vocabulary. Three additive context properties. Six fixture defect patches. The package is ready for v0.1.1 release tagging once external review concludes.
