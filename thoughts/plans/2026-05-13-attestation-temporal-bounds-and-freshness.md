# Plan 7d — Attestation temporal bounds + source freshness + identity/authority disambiguation

**Status:** Draft for review · **Target repo:** `PKAF` · **Parent stack:** `/Users/mikewolfd/Work/formspec-stack`

## Context

Plan 7c shipped the L4 behavioral runtime end-to-end. After Plan 7c landed, a cross-stack scan against `policy-studio/schemas/` and `thoughts/specs/2026-05-12-pkaf-as-public-schema-interop-framework.md` Appendix A asked: with Plan 7a-7c complete, does PKAF have everything it needs to retire ~half of the policy-studio schemas? A semi-formal validation via the code-scout agent answered: yes for 8 of 9 knowledge-shaped schemas, with a small punch list of gap candidates. The first-pass plan proposed promoting three new primitives (`OriginClass`, `Waiver`, `SourceDocument`). Code-scout falsified all three:

| Proposal | Scout verdict | Why |
|---|---|---|
| `rkaf:OriginClass` (6-value AI/human enum) | DROP | Duplicates `#AssertionOrigin` (`constraints/core/assertion.cue:4-9`); name-collides with Studio's existing `OriginClass` (different axis: supply-chain provenance). Promotion creates a parallel competing taxonomy. |
| `rkaf:Waiver` class | DOWNGRADE-TO-PROPERTY | Concept is universal, but Studio's implementation is four parallel un-unified data clumps marked `*substrate-pending*` (`policy-studio/specs/readiness-validation.md:265-276`). Promoting hardens an unfinished design. |
| `rkaf:SourceDocument` class | DOWNGRADE-TO-PROFILE | The `kind` enum (`regulation|statute|policy-manual|sop|memo|...`) is authoring-domain flavored. `#Artifact` + ELI/USLM/DOI/CID schemes already cover federation transport. Per §5.2, profile-scope content. |

This plan executes the **revised, narrower scope** that survives the falsification pass.

A second verification pass after the scout's report surfaced one further reducer: PKAF findings are not IRI-addressable today, so the `targetFinding` field proposed for the Waiver-via-Attestation path can't be honored without a separate `rkaf:Finding` decision. That's deferred.

## Goal

Ship four optional fields + two normative spec edits that close the universal portions of the Studio integration gap without adding any new universal classes. Net new closed taxonomies: 0. Net new universal classes: 0. Conceptual debt: ~0.

After this:
- Time-bounded attestations are expressible. `Attestation.hasEffectivePeriod` + `Attestation.revokedAt` cover "this attestation is valid through Q4" and "this attestation was retracted as of date X" — universal across legal, scientific, editorial, and AI-substrate use cases.
- Freshness — distinct from lifecycle state — is expressible. `lastVerifiedAt` + `verifiedBy` on `SourceFragment` / `EvidenceBinding` / `BridgeValidationResult` answer "when did someone last confirm this source/binding/validation still holds?" without conflating with stale/retired/withdrawn.
- The identity boundary is normatively named. §4.6's existing "Anchoring is dependency-inverted" pattern extends to identity: PKAF references identities by IRI; identity shape itself is binding-territory. Bindings know what they own.
- Content authority (`Warrant`) and user-role authority (`AuthorityGrant`) are disambiguated in §3. Same English word today; readers conflate.

Studio can retire 8 of its 9 knowledge-shaped schemas (identity-subject remains Studio-owned per §4.6) after this lands, using `Attestation` + the new fields to express what `wos-studio-readiness.waiver*` and `wos-studio-source-authority.freshnessSignal` carry today.

## What this plan explicitly does NOT do

- **Promote `OriginClass`, `Waiver`, or `SourceDocument`** as universal vocab classes. Each was falsified by the code-scout pass.
- **Add `targetFinding` to `Attestation`.** Cannot land cleanly until `rkaf:Finding` is IRI-addressable (ADR-0092 is the pre-req).
- **Add runtime behavioral contracts** consuming the new fields. Plan 7e territory after fixtures exercise the shape.
- **Touch identity primitives.** PKAF doesn't own this per the (now-explicit) §4.6 extension.
- **Promote Studio's supply-chain `OriginClass`** (the 5-value `source|approved-interpretation|local-practice|assumption|runtime-observed` axis). Better promotion candidate than the one originally proposed, but needs its own RFC + naming work (avoid colliding with `rkaf:AssertionOrigin`).
- **Resolve `cascade::is_active` asymmetry** — Plan 7c made malformed `effectivePeriodStart`/`End` error loudly (`cascade.rs:171-184`) but left dangling `hasEffectivePeriod` IRI lookups silently active (`cascade.rs:157-159`). Inconsistent strictness. Out of Plan 7d scope; tracked for Plan 7e or a 7d-adjacent ADR.

## Risks + mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `lastVerifiedAt` semantics drift from `consumerLifecycleState` semantics | Medium | §3 entry explicitly disambiguates: freshness = "when last reconfirmed against source"; lifecycle = "whether the assertion is in force." Add a §5 normative invariant: `lastVerifiedAt` MUST NOT be used to gate lifecycle decisions; lifecycle MUST NOT be used to gate freshness. |
| Reusing `rkaf:hasEffectivePeriod` on Attestation collides semantically with Authority/ApplicabilityScope usage | Low | Intentional. Same predicate, same Range (`EffectivePeriod`), same semantics — "this thing is valid within this interval." `cascade::is_active` already reads this edge correctly; extending the domain to Attestation requires zero runtime change. §3 entry clarifies the domain expansion. |
| `revokedAt` overlaps with attestation supersession semantics | Low | PKAF has no attestation-supersession edge today. `revokedAt` is the only retraction mechanism. If/when supersession lands, `revokedAt` becomes a derived field. |
| Plan 7e depends on field semantics being right | Medium | Phase F review catches drift before runtime contracts ossify the shape. |
| Spec edits collide with concurrent vocabulary edits | Low | Greenfield, single-author. No concurrent stream. |
