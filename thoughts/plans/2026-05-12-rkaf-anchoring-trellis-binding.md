**Tech Stack:** Rust 1.79+ (Trellis side, integrating with Trellis's existing crates), JSON-LD canonicalization (URDNA2015 via `oxigraph` or `json-ld` crate), the `rkaf` Rust SDK from Plan 6.

```markdown
## 7. Anchoring contract (abstract) [Normative]

A Rulespec assertion or overlay MAY be cryptographically anchored. This section defines the **abstract anchoring contract**. Concrete bindings (Trellis, COSE_Sign1, JWS, W3C Verifiable Credentials, Sigstore, IPFS+IPNS, content-addressed storage) implement the contract.

### 7.1 Dependency direction
Bindings depend on Rulespec. Rulespec does not depend on, name as authoritative, or import any specific binding. A binding's specification document lives in the binding's own repository, not under Rulespec's spec surface.

The conformance fixture suite (§10) includes one reference binding for fixture purposes; that binding is selected by the editor team and named in the suite manifest, not in this document.

### 7.2 Properties

```turtle
?assertion rkaf:anchoredBy ?anchorIRI .
?anchorIRI rkaf:anchorType ?anchorTypeURI .
# Remaining anchor structure is binding-defined.
```

- `rkaf:anchoredBy` (cardinality 0..*) — IRI(s) of anchor(s) committing to this assertion / overlay.
- `rkaf:anchorType` (cardinality 1..1 on each anchor IRI) — URI identifying the binding (e.g., `urn:rkaf:anchor:trellis/1`, `urn:rkaf:anchor:cose-sign1`, `urn:rkaf:anchor:vc-data-integrity`, `urn:rkaf:anchor:sigstore`).

### 7.3 Binding obligations [Normative]

Any binding implementation MUST:

1. **Define its anchor type.** A URI of the form `urn:rkaf:anchor:<binding>/<version>`. The URI MUST be globally unique and stable across the binding's release cycle.
2. **Define what the anchor commits to.** A canonical serialization function over the Rulespec subgraph being anchored, such that re-anchoring the same subgraph produces a verifiable equality test. Implementations SHOULD use URDNA2015 canonical N-Quads over the JSON-LD-expanded form unless the binding has a stronger reason for a different canonicalization.
3. **Define verification.** A function `verify(graph, anchor) → commit | no-commit` that, given an anchor and the Rulespec subgraph, returns whether the anchor commits to the subgraph as currently presented.
4. **Publish its specification.** As a separate document outside this framework. The document MUST be linked from the binding's anchor type URI (URI dereferenceable to documentation).

### 7.4 What anchoring proves and does not prove [Normative]

Cryptographic anchoring commits that:
- A graph existed at a point in time.
- An actor signed it.
- Bytes have not changed since signing.

Cryptographic anchoring does **NOT** establish:
- That a claim is true.
- That a warrant is valid.
- That an assertion is operationally eligible (warrant validity, applicability, and access scope are independent axes per §1.6).
- That source content cited by the assertion still exists or is unchanged (use Artifact identifier scheme + supersession to track that).

Implementations MUST NOT collapse these distinctions. An anchored assertion is no more truth-warranted than an unanchored one — anchoring proves provenance integrity, not propositional truth.

### 7.5 Multiple bindings
An assertion MAY carry multiple anchors via repeated `rkaf:anchoredBy` triples. Each anchor's binding type is identified by its own `rkaf:anchorType`. Consumers verifying an assertion SHOULD check every anchor whose binding they trust; consumers MAY ignore anchors whose binding they do not trust.

### 7.6 Fixture obligations
Every binding implementation that wishes to be cited as a Rulespec-conformant binding MUST publish a fixture set that:
- Anchors at least one fixture from `fixtures/v0.2/anchoring/` cleanly.
- Verifies cleanly after canonical round-trip (parse → canonicalize → re-parse → verify).
- Fails verification when a single triple in the anchored subgraph is mutated.
```

# Trellis ↔ Rulespec Binding — v1

**Status:** Pre-release, normative within the Trellis repo.
**Implements:** Rulespec abstract anchoring contract `https://rulespec.org/spec/anchoring/contract-v0.2.md`.
**Anchor type URI:** `urn:rkaf:anchor:trellis/1`.

## 1. Posture
This binding lives in the Trellis repository because the dependency direction is *Trellis depends on Rulespec*. Rulespec defines the abstract contract; this document defines how Trellis implements it.

## 2. Canonicalization
The Rulespec subgraph being anchored is:
1. Extracted from the input JSON-LD document by selecting all triples in the `rkaf:` namespace plus all triples reachable via `rkaf:anchoredBy` / `rkaf:hasEvidenceBinding` / `rkaf:bindsSourceFragment` traversal.
2. Expanded via JSON-LD 1.1 expansion against `https://rulespec.org/context/rkaf-context-v0.2.jsonld`.
3. Canonicalized to N-Quads via URDNA2015 (RDF Dataset Canonicalization Algorithm).
4. UTF-8 encoded.

The resulting byte sequence is the *commitment payload*.

## 3. Commit operation
Trellis's anchor over a commitment payload is a COSE_Sign1 structure (RFC 9052) signed by the Trellis case-ledger signing key for the case the assertion belongs to. The COSE_Sign1 payload field is `null`; the `external_aad` field carries the SHA-256 hash of the commitment payload (RFC 9052 §4.4 detached signing).

The anchor IRI is `urn:trellis:anchor:<case-id>:<event-seq>` and is recorded in the case ledger as a Trellis event of type `RkafAnchor` carrying the COSE_Sign1 bytes plus the commitment payload SHA-256.

## 4. Verify operation
Given a Rulespec subgraph and an anchor IRI:
1. Look up the anchor IRI in the Trellis case ledger; recover the COSE_Sign1 bytes and the commitment payload SHA-256.
2. Re-canonicalize the input subgraph per §2; re-hash; assert byte-equality with the recorded SHA-256.
3. Verify COSE_Sign1 against the case's signing key.
4. Return COMMIT iff both checks pass.

## 5. Conformance fixtures
The Trellis binding MUST anchor and round-trip-verify the three fixtures under `rulespec/fixtures/v0.2/anchoring/`. The Rust crate `trellis-rkaf` includes these fixtures under `tests/reference_fixtures.rs`.

## 6. Versioning
Anchor type URI carries a `/<version>` suffix. Future binding versions take a new URI (e.g., `urn:rkaf:anchor:trellis/2`); the v1 anchor type remains valid for fixtures and assertions emitted under v1.

## 7. Non-commitments
Per `https://rulespec.org/spec/anchoring/contract-v0.2.md` §3, this anchor proves provenance integrity — that the Rulespec subgraph existed at signing time, was signed by the case-ledger key, and has not been mutated. It does NOT establish that the assertion's claim is true, that the warrant is valid, or that the assertion is operationally eligible.
```

// trellis/crates/trellis-rkaf/src/lib.rs
pub mod canonicalize;
pub mod commit;
pub mod verify;

use anyhow::Result;
use serde_json::Value;

pub const ANCHOR_TYPE_URI: &str = "urn:rkaf:anchor:trellis/1";

pub struct AnchorRef {
    pub anchor_iri: String,
    pub commitment_sha256: [u8; 32],
}

/// Anchor a Rulespec subgraph extracted from the input document.
/// Returns the anchor IRI to be inserted into the Rulespec graph as
/// `<assertion> rkaf:anchoredBy <anchor_iri>` and `<anchor_iri> rkaf:anchorType "urn:rkaf:anchor:trellis/1"`.
pub fn anchor(rkaf_subgraph: &Value, case_ledger: &mut trellis_case_ledger::Ledger) -> Result<AnchorRef> {
    let canonical = canonicalize::canonicalize(rkaf_subgraph)?;
    let sha = commit::sha256(&canonical);
    let cose = commit::cose_sign1_detached(case_ledger.signing_key(), &sha)?;
    let event_seq = case_ledger.append_rkaf_anchor_event(&cose, &sha)?;
    let anchor_iri = format!("urn:trellis:anchor:{}:{}", case_ledger.case_id(), event_seq);
    Ok(AnchorRef { anchor_iri, commitment_sha256: sha })
}

/// Verify that the anchor commits to the input Rulespec subgraph.
pub fn verify(rkaf_subgraph: &Value, anchor_iri: &str, case_ledger: &trellis_case_ledger::Ledger) -> Result<bool> {
    let event = case_ledger.lookup_rkaf_anchor_event(anchor_iri)?;
    let canonical = canonicalize::canonicalize(rkaf_subgraph)?;
    let sha = commit::sha256(&canonical);
    if sha != event.commitment_sha256 { return Ok(false); }
    verify::cose_sign1_detached(&event.cose_bytes, &sha, case_ledger.verifying_key())
}
```

// trellis/crates/trellis-rkaf/src/canonicalize.rs
use anyhow::Result;
use serde_json::Value;

/// URDNA2015 canonical N-Quads over the JSON-LD-expanded subgraph.
pub fn canonicalize(rkaf_subgraph: &Value) -> Result<Vec<u8>> {
    use oxigraph::store::Store;
    use oxigraph::io::RdfFormat;
    let store = Store::new()?;
    let body = serde_json::to_vec(rkaf_subgraph)?;
    store.load_from_reader(RdfFormat::JsonLd, body.as_slice())?;
    let mut out = Vec::new();
    // oxigraph emits canonical N-Quads via canonical_nquads serializer when configured;
    // for v1 we use sorted N-Quads as a deterministic substitute and tighten to true URDNA2015
    // when the dependency exposes the algorithm directly.
    let mut quads: Vec<String> = store.iter().map(|q| {
        let q = q.unwrap();
        format!("{q} .")
    }).collect();
    quads.sort();
    for q in quads { out.extend_from_slice(q.as_bytes()); out.push(b'\n'); }
    Ok(out)
}
```
